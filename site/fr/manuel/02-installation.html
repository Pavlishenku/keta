Chapitre 2 Installation

2.1 Principe#

Le module Python keta est une extension compilée : le noyau de calcul, écrit en C++, est livré avec sa liaison Python dans un même paquet. Il s'installe de trois façons, de la plus simple à la plus complète : une roue précompilée (fichier .whl), l'archive source compilée par pip, ou la construction directe depuis le dépôt.

Le paquet ne dépend d'aucune autre bibliothèque Python ; il s'utilise avec Python 3.10 ou plus récent, sous Windows, Linux ou macOS.

2.2 Installation par pip#

2.2.1 Roue précompilée#

Lorsqu'une roue correspond au système et à la version de Python, l'installation est immédiate. Il est conseillé de travailler dans un environnement virtuel propre au projet :

python -m venv .venv
.venv\Scripts\activate            (Windows)
source .venv/bin/activate         (Linux, macOS)
pip install keta-1.0.0-cp313-cp313-win_amd64.whl

Le nom du fichier indique la version de Python (cp313 : Python 3.13) et la plateforme (win_amd64, manylinux, macosx). Les roues sont produites pour chaque version publiée par l'intégration continue du dépôt ; le répertoire dist des sources reçoit, pour chaque version, celle de Windows.

2.2.2 Archive source#

À défaut de roue, pip compile le paquet lui-même à partir de l'archive source ou du dépôt ; il télécharge CMake et Ninja s'il le faut. Il suffit d'un compilateur C++20 : sous Windows, les « Build Tools » de Visual Studio 2022 (charge de travail « Développement Desktop en C++ ») ; sous Linux, GCC 13 ou plus récent.

pip install keta-1.0.0.tar.gz        (archive source)
pip install .                       (à la racine du dépôt)

La compilation complète du noyau demande de dix à vingt minutes.

2.3 Construction depuis le dépôt#

Pour suivre le développement ou exécuter les tests, on construit le module avec CMake :

cmake -S . -B build -G Ninja
cmake --build build --target _keta

La construction écrit le paquet dans build/python/keta. On le rend visible de Python par la variable PYTHONPATH :

export PYTHONPATH=/chemin/vers/keta/build/python      (Linux, macOS)
set PYTHONPATH=C:\chemin\vers\keta\build\python       (Windows)
python -c "import keta; print(keta.__version__)"
Option CMakeDéfautEffet
-DKETA_PYTHON=ON|OFFONconstruit ou non le module Python
-DKETA_NATIVE=ONOFFoptimise pour le processeur de la machine de construction ; le module n'est alors utilisable que sur des processeurs compatibles
-DPython3_EXECUTABLE=…—choisit l'interpréteur Python visé lorsque plusieurs sont installés
Important

Le module compilé n'est utilisable qu'avec la version de Python qui a servi à le construire : le nom de la bibliothèque porte cette version (par exemple _keta.cpython-313-x86_64-linux-gnu.so ou _keta.cp313-win_amd64.pyd).

2.4 Éditeur de code#

Le paquet contient la description complète de ses types (fichiers .pyi) : un éditeur comme Visual Studio Code, avec l'extension Python, propose donc la complétion des méthodes, affiche leur documentation au survol et signale les arguments mal nommés avant toute exécution.

2.5 Vérification de l'installation#

Les exemples de ce manuel servent à vérifier l'installation. Le script suivant exécute chacun d'eux et compare sa sortie, caractère pour caractère, à la sortie reproduite dans le manuel ; il utilise le module installé, ou celui du répertoire donné par --module :

python3 examples/manuel/executer_tous.py

Chaque exemple conforme est signalé par OK ; le script se termine par le nombre d'exemples conformes et renvoie un code de sortie nul si tous le sont. Un écart est affiché sous la forme d'une différence ligne à ligne.

Le plus petit calcul possible confirme le bon fonctionnement du module :

Exempleexamples/manuel/ex_console.py
# Premier calcul : console en acier IPE 300 de 4 m chargée en bout.
import json
import keta

m = keta.Model()
a = m.add_node(0.0, 0.0, 0.0)            # encastrement
b = m.add_node(4.0, 0.0, 0.0)            # extrémité libre
acier = m.steel()                        # E = 210 GPa, nu = 0,3
ipe = m.add_section("IPE300")
poutre = m.add_beam(a, b, section=ipe, material=acier)
m.fix(a)
m.add_point_load(b, fz=-10e3)            # 10 kN vers le bas (cas 1)

res = m.analyze()
cas = res.case(1)
ux, uy, uz, rx, ry, rz = cas.displacement(b)
print(f"flèche en bout     uz = {uz * 1e3:.4f} mm")
print(f"rotation en bout   ry = {ry * 1e3:.4f} mrad")
noeud, (fx, fy, fz, mx, my, mz) = cas.reactions()[0]
print(f"réaction au noeud {noeud} : Fz = {fz / 1e3:.3f} kN, My = {my / 1e3:.3f} kN.m")

# Contrôle : flexion + effort tranchant (poutre de Timoshenko), avec les
# caractéristiques effectivement retenues pour la section (modèle JSON)
p = json.loads(m.to_json())["sections"][0]["props"]
E, G = 210e9, 210e9 / (2 * 1.3)
w = -10e3 * 4.0**3 / (3 * E * p["Iy"]) - 10e3 * 4.0 / (G * p["Avz"])
print(f"forme fermée       uz = {w * 1e3:.4f} mm")
assert abs(uz - w) < 1e-9 * abs(w)
Sortie obtenue
flèche en bout     uz = -12.3958 mm
rotation en bout   ry = 4.5590 mrad
réaction au noeud 1 : Fz = 10.000 kN, My = -40.000 kN.m
forme fermée       uz = -12.3958 mm

2.6 Paramètres d'exécution#

La factorisation des grands systèmes peut être répartie sur plusieurs cœurs de calcul. Le nombre de fils d'exécution est un réglage global du processus :

Syntaxe
keta.set_solver_threads(n)
keta.solver_threads()  →  int
ParamètreUnitéDéfautSignification
n—1nombre de fils de la factorisation supernodale : 1 = séquentiel, 0 = tous les cœurs disponibles

Les résultats sont identiques bit pour bit quel que soit le nombre de fils. Le parallélisme n'est utile que pour les modèles de grande taille.

2.7 Reconstruction de ce manuel#

Le présent document est produit à partir de ses sources HTML par :

python3 tools/build_manuel_python.py --module build/python

Le script vérifie d'abord tous les exemples (la construction s'arrête si l'un d'eux échoue ou si sa sortie a changé), puis met en page le document par le navigateur Chromium, piloté par Playwright depuis Node.js. Le résultat est écrit dans docs/keta_manuel_python.pdf. L'option --doc principes construit de la même façon le manuel des principes de calcul (docs/keta_principes_de_calcul.pdf), et --doc tous les deux.

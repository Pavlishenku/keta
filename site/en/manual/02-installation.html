Chapter 2 Installation

2.1 Principle#

The Python module keta is a compiled extension: the calculation kernel, written in C++, is delivered with its Python binding in a single package. It can be installed in three ways, from the simplest to the most complete: a prebuilt wheel (.whl file), the source archive compiled by pip, or a direct build from the repository.

The package depends on no other Python library; it is used with Python 3.10 or later, under Windows, Linux or macOS.

2.2 Installation with pip#

2.2.1 Prebuilt wheel#

When a wheel matches the system and the Python version, installation is immediate. It is advisable to work in a virtual environment specific to the project:

python -m venv .venv
.venv\Scripts\activate            (Windows)
source .venv/bin/activate         (Linux, macOS)
pip install keta-1.0.0-cp313-cp313-win_amd64.whl

The file name gives the Python version (cp313: Python 3.13) and the platform (win_amd64, manylinux, macosx). The wheels are produced for each published version by the continuous integration of the repository; the dist directory of the sources receives, for each version, the Windows one.

2.2.2 Source archive#

Failing a wheel, pip compiles the package itself from the source archive or from the repository; it downloads CMake and Ninja if necessary. A C++20 compiler is all that is needed: under Windows, the Visual Studio 2022 “Build Tools” (workload “Desktop development with C++”); under Linux, GCC 13 or later.

pip install keta-1.0.0.tar.gz        (source archive)
pip install .                       (at the root of the repository)

The full compilation of the kernel takes ten to twenty minutes.

2.3 Building from the repository#

To follow development or run the tests, the module is built with CMake:

cmake -S . -B build -G Ninja
cmake --build build --target _keta

The build writes the package to build/python/keta. It is made visible to Python through the PYTHONPATH variable:

export PYTHONPATH=/path/to/keta/build/python      (Linux, macOS)
set PYTHONPATH=C:\path\to\keta\build\python       (Windows)
python -c "import keta; print(keta.__version__)"
CMake optionDefaultEffect
-DKETA_PYTHON=ON|OFFONbuilds the Python module or not
-DKETA_NATIVE=ONOFFoptimises for the processor of the build machine; the module can then be used only on compatible processors
-DPython3_EXECUTABLE=…—selects the target Python interpreter when several are installed
Important

The compiled module can be used only with the Python version that was used to build it: the name of the library carries this version (for example _keta.cpython-313-x86_64-linux-gnu.so or _keta.cp313-win_amd64.pyd).

2.4 Code editor#

The package contains the full description of its types (.pyi files): an editor such as Visual Studio Code, with the Python extension, therefore provides completion of the methods, shows their documentation on hover and flags misnamed arguments before any run.

2.5 Checking the installation#

The examples of this manual serve to check the installation. The following script runs each of them and compares its output, character by character, with the output reproduced in the manual; it uses the installed module, or the one in the directory given by --module:

python3 examples/manual/executer_tous.py

Each conforming example is reported by OK; the script ends with the number of conforming examples and returns a zero exit code if all of them conform. A discrepancy is shown as a line-by-line difference.

The smallest possible analysis confirms that the module works correctly:

Exampleexamples/manual/ex_console.py
# First analysis: 4 m IPE 300 steel cantilever loaded at its tip.
import json
import keta

m = keta.Model()
a = m.add_node(0.0, 0.0, 0.0)            # fixed support
b = m.add_node(4.0, 0.0, 0.0)            # free end
steel = m.steel()                        # E = 210 GPa, nu = 0.3
ipe = m.add_section("IPE300")
beam = m.add_beam(a, b, section=ipe, material=steel)
m.fix(a)
m.add_point_load(b, fz=-10e3)            # 10 kN downwards (case 1)

res = m.analyze()
case_ = res.case(1)
ux, uy, uz, rx, ry, rz = case_.displacement(b)
print(f"tip deflection     uz = {uz * 1e3:.4f} mm")
print(f"tip rotation       ry = {ry * 1e3:.4f} mrad")
node, (fx, fy, fz, mx, my, mz) = case_.reactions()[0]
print(f"reaction at node {node}: Fz = {fz / 1e3:.3f} kN, My = {my / 1e3:.3f} kN.m")

# Check: bending + shear (Timoshenko beam), with the properties
# actually used for the section (JSON model)
p = json.loads(m.to_json())["sections"][0]["props"]
E, G = 210e9, 210e9 / (2 * 1.3)
w = -10e3 * 4.0**3 / (3 * E * p["Iy"]) - 10e3 * 4.0 / (G * p["Avz"])
print(f"closed form        uz = {w * 1e3:.4f} mm")
assert abs(uz - w) < 1e-9 * abs(w)
Output
tip deflection     uz = -12.3958 mm
tip rotation       ry = 4.5590 mrad
reaction at node 1: Fz = 10.000 kN, My = -40.000 kN.m
closed form        uz = -12.3958 mm

2.6 Run-time parameters#

The factorisation of large systems can be distributed over several processor cores. The number of threads is a global setting of the process:

Syntax
keta.set_solver_threads(n)
keta.solver_threads()  →  int
ParameterUnitDefaultMeaning
n—1number of threads of the supernodal factorisation: 1 = sequential, 0 = all available cores

The results are identical bit for bit whatever the number of threads. Parallelism is useful only for large models.

2.7 Rebuilding this manual#

This document is produced from its HTML sources by:

python3 tools/build_manuel_python.py --module build/python --lang en

The script first checks all the examples (the build stops if one of them fails or if its output has changed), then lays out the document with the Chromium browser, driven by Playwright from Node.js. The result is written to docs/keta_python_manual.pdf. The option --doc principes builds the manual of calculation principles in the same way (docs/keta_calculation_principles.pdf), and --doc tous both.

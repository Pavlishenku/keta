Chapter 4 Organisation of an analysis

4.1 Course of a script#

A keta analysis is a Python script that chains four steps:

  1. import of the module: import keta;
  2. description of the model: creation of a keta.Model() object, then calls to its add_… methods to define nodes, materials, sections, elements, supports, links and loads;
  3. running of one or several analyses: m.analyze() for linear statics, m.modal(), m.buckling(), m.phased(), etc. Each analysis returns an independent results object; the model is not modified;
  4. processing of the results: reading of displacements, reactions and internal forces through the methods of the results objects, printing, additional calculations in Python.

The steps can be repeated: a model can be completed after a first analysis and then analysed again, several models can coexist in the same script, and a model can be built by a parametrised Python function (Chapter 21).

4.2 Identifiers#

All the add_… methods that create an object return its identifier, an integer. Identifiers are assigned automatically, in the order of creation, separately for each family of objects: the first node has number 1, the first bar number 1, the first material number 1, etc. These identifiers are kept in Python variables or lists for later use:

a = m.add_node(0, 0, 0)                 # a == 1
b = m.add_node(6, 0, 0)                 # b == 2
steel = m.steel()                       # material 1
beam = m.add_beam(a, b, m.add_section("IPE300"), steel)    # bar 1

The separately numbered families are: nodes, bars (beams and trusses), cables, materials, sections, links, shells, continuum elements, tendons, combinations. It is not possible to choose a number oneself; the correspondence with an external numbering is made with a Python dictionary.

Important

Identifiers are integers without geometric meaning. An identifier of one family must not be used for another (a node number instead of a bar number): depending on the case, the error is reported (KeyError) or applies to another existing object.

4.3 Load cases#

Loads are grouped into load cases identified by an integer number chosen by the user and passed through the case parameter of the loading methods (default value 1). A case is created by the first load that refers to it; it can be named by m.name_case. The cases are analysed together, in a single factorisation of the stiffness matrix. Linear combinations of cases are defined by m.add_combination (Chapter 19).

Note

m.harmonic and m.psd (Chapter 14) designate the case by its number with the argument case_id; their argument case gives its rank (0 for the first case in increasing order of numbers).

4.4 Results#

Each analysis returns an object specific to the analysis. Linear statics returns a Results object, which gives access to the results of each case (r.case(i)) and of each combination (r.combo(j)) in the form of CaseResult objects. The main reading methods are common to most static analyses:

MethodResult
displacement(node)tuple (dx, dy, dz, rx, ry, rz), global axes
reactions()list of (node, (Fx, Fy, Fz, Mx, My, Mz)) of the supported nodes
sum_reactions()resultant (Fx, Fy, Fz) of the reactions
bar_forces(bar)list of (x/L, N, Vy, Vz, T, My, Mz) at the output stations
end_forces(bar)the 12 end forces, local axes
max_displacement()largest nodal translation (norm)

Chapter 20 describes all the results objects and Appendix B the format of each.

4.5 Annotated example#

The example below illustrates the organisation of a complete script: a two-span continuous beam on an elastic central support, whose reaction is compared with the closed form.

Exampleexamples/manual/ex_appuis.py
# Rigid and elastic supports: continuous beam of 2 x 8 m, elastic central support.
import keta

L, q, ks = 8.0, -30e3, 20e6          # span [m], load [N/m], stiffness [N/m]
m = keta.Model()
n = [m.add_node(L * i, 0.0, 0.0) for i in range(3)]
sec = m.add_section_props(sx=0.05, iy=2.0e-3, iz=1.0e-3, ix=1.0e-3)   # rigid in shear
mat = m.add_material(e=30e9, nu=0.2)
b = [m.add_beam(n[i], n[i + 1], sec, mat) for i in range(2)]

m.add_support(n[0], dx=True, dy=True, dz=True, rx=True)   # pinned support (rotations ry, rz free)
m.add_support(n[1], dy=True, kz=ks)                       # elastic vertical support
m.add_support(n[2], dy=True, dz=True)                     # sliding support
for bi in b:
    m.add_udl(bi, wz=q)

case_ = m.analyze().case(1)
for nd, (fx, fy, fz, mx, my, mz) in case_.reactions():
    print(f"node {nd}: Fz = {fz / 1e3:9.3f} kN")
w1 = case_.displacement(n[1])[2]
print(f"settlement of the elastic support: {w1 * 1e3:.3f} mm")

# Check (closed form): R1 = (5 q (2L)^4 / 384 EI) / (1/ks + (2L)^3 / 48 EI)
EI, Lt = 30e9 * 2.0e-3, 2 * L
R1 = (5 * -q * Lt**4 / (384 * EI)) / (1 / ks + Lt**3 / (48 * EI))
print(f"expected reaction: {R1 / 1e3:.3f} kN")
assert abs(dict(case_.reactions())[n[1]][2] - R1) < 1e-8 * R1
assert abs(w1 + R1 / ks) < 1e-12
Output
node 1: Fz =    95.094 kN
node 2: Fz =   289.811 kN
node 3: Fz =    95.094 kN
settlement of the elastic support: -14.491 mm
expected reaction: 289.811 kN

The script creates three nodes (n is the list of their identifiers), a section defined by its properties and a material, then two bars. The left support restrains the three translations and torsion; the central support restrains the transverse translation dy and carries a vertical spring kz; the right support slides along X. A vertical distributed load is applied to both bars in case 1, the default case. After the analysis, the loop over case_.reactions() prints the vertical reactions; the reaction of the elastic support is then checked against the closed form.

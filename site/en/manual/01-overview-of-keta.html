Chapter 1 Overview of keta

1.1 Introduction#

keta is a structural analysis kernel written in C++. It handles three-dimensional or plane bar structures, slabs and walls modelled as thin or thick shells, and two- and three-dimensional continua. It is mainly intended for the analysis of bridges and civil engineering frames.

The kernel is driven from the Python language by the keta module. A model is described by a script: creation of the nodes, materials, sections, elements, supports and loads, then running of the analyses and processing of the results. All the features of the Python language (loops, functions, lists, numerical computation) serve to parametrise the structure and to process the results; there is no data language specific to keta.

The main features available from Python are the following:

  • the description of bar structures (Timoshenko beams with 12 degrees of freedom, truss bars, cables as elastic catenaries), with offsets, hinges, section orientation, Winkler elastic foundation and links between nodes;
  • triangular flat shell facets (membrane and bending, orthotropy, laminates), plane, axisymmetric and solid continuum elements;
  • sections from the European catalogue (IPE, HEA, HEB, HEM), parametric sections and directly given section properties;
  • fixed loads (self-weight, nodal loads, loads on bars, temperatures, support displacements, surface loads, hydrostatic pressures) and their combinations;
  • prestressing by tendons (friction, anchorage draw-in, time-dependent losses) and staged construction with creep, shrinkage and relaxation according to the main code laws;
  • live loads by influence lines and surfaces: load models of EN 1991-2 (road, rail, fatigue), load systems of Fascicule 61 Titre II, arbitrary vehicles;
  • dynamics: mode shapes, spectral analysis, harmonic response, power spectral density, linear and nonlinear time-history analyses, passage of high-speed trains;
  • wind: profiles, turbulence, response to turbulent wind, equivalent static loads, flutter;
  • stability: linear buckling, imperfections, second order, large displacements, arc length and collapse load;
  • nonlinear link laws (tension only, gap, tabulated laws), soil springs and earth pressure;
  • fire analysis of reinforced concrete bars (temperature field in the section, hot stiffnesses, search for equilibrium) and the properties of materials at high temperature;
  • section checking tools (reinforced concrete, shells, composite beams).

The results are returned as Python numbers, tuples and lists. They lend themselves directly to the production of tables, the writing of files or the plotting of curves with the usual libraries.

1.2 Characteristics of the kernel#

The kernel uses the exact solution of the chosen mechanical model wherever one is available. This applies to the internal forces at the output stations of Timoshenko beams, which are recomputed by equilibrium, to the elastic catenary of cables, to the integration of distributed loads and to the search for extreme combinations. An unsupported configuration raises an error; it is not replaced by an approximation without the user's knowledge.

The analyses are deterministic: the same script produces the same numbers, bit for bit, from one run to the next and whatever the number of threads used by the solver. The outputs of the examples reproduced in this manual can therefore be obtained again without any difference.

1.3 Limits#

The number of nodes, bars and load cases is limited only by the available memory. Linear systems are solved by a supernodal sparse factorisation; the size of the models commonly handled (a few tens of thousands of degrees of freedom) poses no difficulty.

The Python module exposes only part of the features of the C++ kernel. Functions that do not yet have a Python interface are flagged in the text by a “Pending” box; Appendix C lists them. They cannot be used from a script.

Pending

Example of a box: a feature flagged in this way exists in the calculation kernel but is not yet accessible from Python. The text describes its principle; the syntax will be documented when the interface is available.

1.4 Writing conventions#

1.4.1 Command syntax#

Each command is presented in a syntax box, followed by a table describing its parameters, by notes and by an example. In the boxes:

  • m denotes a model created by m = keta.Model(); r, case_ or res denote results objects;
  • parameters written in the form name=value are optional; the value shown is the default value. Parameters without a value are mandatory;
  • the arrow → indicates the returned value;
  • optional parameters are preferably given by name (m.add_udl(b, wz=-10e3, case=2)), which makes the script readable and independent of the order of the arguments.
Syntax
m.add_udl(bar, wx=0.0, wy=0.0, wz=0.0, case=1, frame='global')

In the parameter table, the “Unit” column gives the expected SI unit and the “Default” column the value taken when the parameter is absent; a dash marks a mandatory parameter.

1.4.2 Notes#

Throughout the manual, notes are presented as follows:

Note

Note: usage detail or additional information.

Important

Important note: a point whose omission leads to a wrong result or to an error.

1.4.3 Examples#

The examples are complete scripts, provided in the directory examples/manual of the repository (examples/manuel for the French edition). Each has been run with the version of the module described by this manual; the output reproduced below the listing is the output actually obtained. The script executer_tous.py of the same directory re-runs all the examples and checks that their outputs are unchanged (Chapter 2). When a closed form exists, the example prints it next to the keta result, or checks it with an assert statement.

Numbers are written with a decimal point, in the text as in the scripts and outputs; the scripts and outputs follow Python notation (decimal point, 1e-3 for 10-3).

1.5 Error detection#

Errors are reported by Python exceptions, which stop the script at the faulty line with an explicit message:

ExceptionCause
KeyErrornon-existent identifier: node, bar, load case, combination, cable, catalogue section, mode shape, etc.
ValueErrorinvalid data (unknown keyword, value out of range, incompatible number of parameters) or impossible analysis (unstable structure, lack of convergence, analysis not applicable to the model).
TypeErrorargument of an unexpected type (list instead of a number, etc.), reported by Python itself.

The method m.validate() checks a model without analysing it and returns the list of problems found (an empty list for a consistent model). These messages, written in English, are those of the calculation kernel.

Exampleexamples/manual/ex_erreurs.py
# Error detection: missing identifier (KeyError), invalid data or analysis (ValueError).
import keta

m = keta.Model()
a, b = m.add_node(0, 0, 0), m.add_node(6, 0, 0)
beam = m.add_beam(a, b, m.add_section_rect(0.2, 0.4), m.steel())
m.add_point_load(b, fz=-1e3)

try:
    m.add_section("IPE999")
except KeyError as e:
    print("KeyError:  ", e)

try:
    m.add_udl(beam, wz=-1.0, frame="oblique")
except ValueError as e:
    print("ValueError:", e)

try:
    m.analyze()                    # no support: mechanism
except ValueError as e:
    print("ValueError:", str(e).splitlines()[0])

m.fix(a)
r = m.analyze()
try:
    r.case(2)
except KeyError as e:
    print("KeyError:  ", e)

m2 = keta.Model()
m2.add_node(0, 0, 0)
m2.add_beam(1, 7, 1, 1)            # non-existent references
print("validate():", m2.validate())
Output
KeyError:   "unknown profile 'IPE999'"
ValueError: frame must be 'global' | 'local' | 'projected', got 'oblique'
ValueError: solver: factorization failed (singular or structurally deficient stiffness)
KeyError:   'no load case 2'
validate(): ['model: unknown node id 7']
Note

An exception can be caught by try … except to continue a script, for example in a parametric study or when a lack of equilibrium has a physical meaning (collapse of a structure in fire, Chapter 18).
